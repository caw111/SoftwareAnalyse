# 1 编制目的、依据与规范状态

## 1.1 编制目的

本规范用于约束学术成果检索与分享平台核心模块的后续设计、编码、测试和人工智能辅助开发活动。本规范将系统需求规格说明书中的功能需求进一步转换为可执行的模块职责、输入输出、业务规则、算法约束、异常处理要求和验收标准。

本规范在代码生成活动开始以前建立。人工智能生成的代码必须遵循本规范已经确定的规则。涉及待会议确认事项的实现活动应在会议形成明确决议以后开展。

## 1.2 编制依据

1. 课程实践任务书要求在需求建模阶段编写系统需求规格说明书和核心模块开发规范，并重点覆盖数据清洗规则、去重与消歧算法、检索排序规则等数据密集型逻辑。
2. 课程实践任务书要求核心模块开发规范说明模块功能、接口与算法约束以及验收标准，并要求规范先于代码进入版本管理。
3. 《学术成果检索与分享平台需求规格说明书v0.1》提供了当前系统边界、业务角色、核心业务对象、功能需求、数据需求、数据完整性规则、关键业务流程、非功能需求、技术方案和验收标准。

## 1.3 规范状态分类

- **已确定**：课程任务书或现有 SRS 已经明确规定，并且本版本直接继承该规定。
- **本版本基线**：现有 SRS 已经给出具体方案，本版本将该方案作为会前实现基线。
- **待会议确认**：现有材料存在多个可选方案，或者现有材料缺少实现细节。人工智能仅能保留接口位置、数据结构位置或测试占位内容，业务决策必须由人工形成结论。

## 1.4 当前系统范围基线

本版本沿用现有 SRS 的一期范围。平台以公开学术元数据为基础，建立本地结构化数据存储和检索索引，提供论文检索、论文详情、科研人员门户、成果认领、机构管理、索引更新申请、数据采集管理、统计分析和相关推荐功能。

本版本以 Crossref 作为论文主数据源的会前基线。OpenAlex 与 Unpaywall 的使用范围列入待会议确认事项。学术成果类型扩展至专利、科研项目和获奖的实现深度列入待会议确认事项。

# 2 核心模块划分与公共开发约束

## 2.1 核心模块划分

| 规范编号 | 核心模块 | 主要职责 | 重点规则 |
|---|---|---|---|
| SPEC-01 | 数据采集与增量同步 | 初始采集、定向采集、增量同步、任务状态管理、失败重试和同步进度管理 | 游标分页、有界时间窗口、幂等任务、重试、任务日志 |
| SPEC-02 | 数据清洗、去重与消歧 | 来源数据转换、字段规范化、论文去重、作者消歧、机构消歧和原始数据保留 | DOI 唯一键、按唯一键新增或更新、ORCID 优先、ROR ID 优先 |
| SPEC-03 | 检索与排序 | 关键词检索、字段检索、过滤、排序、分页、索引同步和结果聚合 | BM25、字段权重、关系数据库作为业务真值源、搜索索引可重建 |
| SPEC-04 | 科研人员门户与成果认领 | 门户、论文认领、审核、撤销、机构申请和索引更新申请 | 角色权限、申请状态、审核过程、来源字段保护、审计记录 |
| SPEC-05 | 统计分析与相关推荐 | 平台统计、科研人员统计、推荐候选生成、排序、去重和推荐原因 | 统计口径、DOI 去重、推荐原因、降级处理 |

## 2.2 公共数据原则

- 关系数据库承担业务真值源职责。搜索索引用于检索和聚合，并且应具备从关系数据库重新构建的能力。
- 外部来源数据应记录来源标识和同步时间。Crossref 原始 JSON 或等价的原始字段快照应保留，用于问题追踪和重新处理。
- 论文主链路以规范化 DOI 作为唯一识别键。重复 DOI 数据进入处理链路时执行按唯一键新增或更新。
- 科研人员账户实体、来源数据中的作者实体和科研人员门户实体采用独立的数据对象。三类对象之间通过明确的认领或绑定关系建立关联。
- 公开元数据采集应遵守数据来源的访问规则和课程数据合规要求。未经授权的论文全文禁止进入平台存储。

## 2.3 公共接口原则

本版本定义逻辑接口和数据契约。具体的 REST 路径、数据库表字段类型、搜索索引映射和消息队列实现形式由后续构件设计阶段确定。接口设计应保留稳定的输入字段、输出字段、错误类型和状态转换语义。

# 3 SPEC-01 数据采集与增量同步

## 3.1 模块目标与范围

数据采集与增量同步模块负责从外部学术元数据来源获取论文数据，并将原始数据提交给数据清洗模块。该模块同时负责任务创建、任务执行、任务停止、失败重试、任务日志、定向补采和同步进度管理。

本版本的外部来源基线为 Crossref。其他数据来源通过独立的数据源适配接口接入，具体启用范围由会议决议确定。

## 3.2 对应需求

本模块对应 SRS 中 FR-CRAWL-001 至 FR-CRAWL-008、FR-SYNC-001 至 FR-SYNC-005，以及索引更新申请中的定向采集要求。

## 3.3 采集规则

1. Crossref 列表型采集采用游标分页方式。批量扫描流程禁止采用传统深分页方式。
2. 初始采集任务应按照明确的数据范围执行。任务范围必须进入任务记录，以便后续追踪和重复执行。
3. 增量同步任务采用具有开始边界和结束边界的固定时间窗口。任务成功完成以后更新同步进度记录。
4. 管理员可以按照 DOI 或 ISSN 创建高优先级定向补采任务。
5. 网络异常、HTTP 429 和 HTTP 5xx 等可恢复错误进入有限次数的重试流程。重试等待时间采用递增方式。
6. 采集任务必须保持幂等性。同一任务重复执行时，论文数据的最终业务状态应保持一致。

## 3.4 任务状态

本版本沿用 SRS 中的任务状态集合：PENDING、RUNNING、SUCCESS、FAILED、RETRYING、STOPPED。状态转换由任务执行器统一管理。

## 3.5 人工智能生成范围

- 人工智能可以生成数据源客户端、参数对象、任务执行框架、游标分页处理、重试逻辑、任务日志代码和基于本规范的单元测试。
- 数据源访问频率、重试次数、重试等待时间上限和任务并发度必须由人工形成明确配置以后进入代码。
- 新增外部数据源、修改增量时间窗口规则、修改任务状态转换规则和修改同步进度推进规则必须经过人工确认。

## 3.6 验收标准

- 管理员能够创建初始采集任务，并且任务记录能够保存完整的采集范围。
- Crossref 列表型采集能够连续使用游标完成多页数据获取。
- 增量同步任务能够保存固定时间窗口，并且仅在任务成功以后推进同步进度记录。
- HTTP 429、HTTP 5xx 和网络异常能够进入有限次数的重试流程，并记录每次错误。
- 相同任务重复执行以后，关系数据库中的论文记录数量符合 DOI 去重规则。
- 管理员能够查看任务状态、处理数量、失败数量和任务日志。

# 4 SPEC-02 数据清洗、去重与消歧

## 4.1 模块目标与范围

数据清洗、去重与消歧模块负责将外部来源的原始论文元数据转换为平台统一数据结构。该模块承担 DOI 规范化、标题文本处理、作者字段处理、ISSN 处理、日期解析、摘要文本处理、URL 处理、空字段识别、论文去重、作者消歧、机构消歧和原始数据保留。

## 4.2 DOI 规范化

1. 系统移除 DOI 字符串首尾的空白字符。
2. 系统将 DOI 字符串中的英文字母统一转换为小写形式。
3. 系统移除 `https://doi.org/`、`http://dx.doi.org/` 和 `doi:` 前缀。
4. 系统将规范化后的 DOI 保存为 `canonical_doi`，并将 `canonical_doi` 作为论文唯一键。
5. 同一 `canonical_doi` 再次进入处理流程时，系统执行按唯一键新增或更新，并更新来源同步时间。

## 4.3 作者消歧

1. 当两个作者记录具有相同且有效的 ORCID 时，系统可以建立自动绑定关系。
2. 当作者记录缺少 ORCID 时，系统保持来源级别的独立作者记录。
3. 姓名与机构信息可以形成候选匹配提示，候选匹配提示仅供人工审核使用。
4. 姓名、合作者、期刊会议和研究领域信息可以用于后续自动消歧算法。该算法进入实现阶段以前必须形成独立的算法规范和测试数据集。
5. 科研人员门户实体与来源作者实体通过成果认领关系建立关联。系统禁止直接将来源作者记录转换为科研人员账户身份。

## 4.4 机构消歧

1. 机构记录优先使用 ROR ID 进行精确识别。
2. 缺少 ROR ID 时，系统可以使用官方域名形成高优先级候选匹配。
3. 规范化机构名称用于形成候选匹配。
4. 重复机构的最终合并操作由管理员执行，并记录审计信息。

## 4.5 人工智能生成范围

- 人工智能可以按照明确规则生成 DOI 规范化、字段解析、格式校验、原始数据保存、按唯一键新增或更新和测试代码。
- 人工智能可以生成作者候选匹配计算代码，候选结果仅进入人工审核流程。
- 作者自动合并规则、机构自动合并规则、名称语义修正规则和多数据源字段覆盖优先级必须由人工形成明确决议。

# 5 SPEC-03 检索与排序

## 5.1 模块目标与范围

检索与排序模块负责论文关键词检索、定向字段检索、条件过滤、结果排序、分页、分面统计、搜索索引同步和检索结果聚合。关系数据库保存业务真值，Elasticsearch、OpenSearch 或华为云 CSS 承担检索索引职责。具体产品选型列入待会议确认事项。

## 5.2 检索输入

关键词检索字段至少包含标题、作者姓名、摘要、期刊或会议名称、DOI、学术领域或标签。过滤条件至少包含年份、学术领域、期刊或会议、作者、出版商、开放获取状态和成果类型。排序方式至少包含相关度、出版时间升序、出版时间降序和 Crossref 引用次数降序。

## 5.3 相关度排序

本版本采用 BM25 作为关键词相关度计算基础。会前测试字段权重如下：

| 字段 | 权重 |
|---|---:|
| DOI | 6 |
| title | 4 |
| author_names | 2.5 |
| venue_name | 2 |
| subjects | 2 |
| abstract | 1 |

最终字段权重必须通过固定测试集进行验证，并由团队会议形成确认记录。

## 5.4 数据一致性

- 关系数据库保存论文业务数据和业务关系。
- 搜索索引保存用于查询、过滤、排序和分面统计的数据副本。
- 数据清洗完成以后触发搜索索引更新。
- 搜索索引更新失败时，系统记录待重建状态和失败原因。
- 系统提供从关系数据库重新构建搜索索引的管理能力。

# 6 SPEC-04 科研人员门户与成果认领

## 6.1 模块目标与范围

科研人员门户与成果认领模块负责科研人员公开门户、论文检索认领、认领申请、管理员审核、错误认领撤销、机构注册申请、科研人员机构认证申请以及论文索引更新申请。

## 6.2 成果认领流程

1. 科研人员按照姓名、DOI 或论文题名检索待认领论文。
2. 科研人员针对目标论文提交成果认领申请。
3. 系统检查当前论文与当前科研人员之间的已认领关系和重复申请记录。
4. 管理员处理认领申请，并记录审核结果和审核意见。
5. 审核通过以后，系统建立 ResearcherProfile 与 Paper 的认领关系。
6. 审核驳回以后，系统保存驳回结果和审核意见。
7. 科研人员可以提交错误认领撤销申请。管理员可以执行错误关系纠正，并记录审计信息。

当前会前版本按照管理员审核流程编制。自动认领规则列入待会议确认事项。

## 6.3 成果信息维护边界

科研人员维护范围限定为平台侧附加信息。Crossref 来源字段的纠错统一通过索引更新申请或数据纠错申请处理。

# 7 SPEC-05 统计分析与相关推荐

## 7.1 统计指标

一期至少覆盖论文总数、作者数量、机构数量、期刊或会议数量、开放获取论文数量及占比、年度论文数量、机构科研人员及论文数量、学术领域论文数量、科研人员个人成果数量、年度分布和引用次数总和。

## 7.2 相关推荐规则

1. 相关推荐候选集合可以由搜索引擎相似内容查询、学术领域匹配和期刊或会议匹配产生。
2. 推荐结果排除当前论文自身。
3. 推荐结果按照 `canonical_doi` 执行去重。
4. 默认返回 8 篇论文，最大返回数量为 20 篇。
5. 每条推荐结果至少返回一个推荐原因标签。
6. 摘要或学术领域字段缺失时，推荐计算采用标题、期刊或会议和年份字段继续执行。

推荐评分公式和各类信号的最终权重列入待会议确认事项。

# 8 公共非功能要求与测试要求

- 课程验收规模下，常规搜索 P95 响应时间达到 2 秒以内。
- 课程验收规模下，论文详情 P95 响应时间达到 1 秒以内。
- 推荐计算的服务等待上限为 1 秒。
- 系统应支持至少 10 万级论文数据运行。
- 课程最终验收数据量至少达到 10,000 条学术成果数据。
- 数据清洗、去重与消歧模块、检索与排序模块、统计计算模块的自动化测试行覆盖率应达到 80% 及以上。
- 平台采集范围限定为公开允许访问的元数据。
- 未经授权的论文全文禁止进入平台存储和分发流程。

# 9 人工智能生成代码的统一范围

## 9.1 人工智能可以直接执行的工作

- 根据已经确定的数据结构生成请求对象、响应对象、数据传输对象和字段映射代码。
- 根据已经确定的规则生成参数校验、格式校验、分页、排序参数转换和通用异常处理代码。
- 根据已经确定的接口契约生成接口控制层、服务调用层和测试代码。
- 根据已经确定的日志要求生成运行日志、任务日志和错误记录代码。
- 根据已经确定的业务规则生成单元测试和集成测试骨架。

## 9.2 人工智能生成以后必须进行人工审查的工作

- Crossref 原始数据到平台领域对象的映射。
- DOI 规范化、论文去重、作者候选匹配和机构候选匹配。
- 搜索查询构建、BM25 字段权重实现和分面统计。
- 任务状态转换、同步进度推进和失败重试。
- 成果认领状态转换、角色权限和管理员审核流程。
- 统计口径实现、推荐候选生成、推荐评分和推荐原因生成。

## 9.3 必须由人工形成决议的事项

- 核心模块的业务边界和模块拆分。
- 外部数据源启用范围以及多个数据源之间的字段优先级。
- 作者自动合并规则和机构自动合并规则。
- 学术领域分类体系和映射规则。
- 搜索字段权重、分词策略、同义词策略和最终排序规则。
- 科研人员身份认证方式、自动认领条件和角色权限边界。
- 统计指标定义、统计分母和推荐评分公式。
- 数据库、搜索引擎、消息队列和任务调度产品的最终选型。
