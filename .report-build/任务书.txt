一、任务概述 
（一）任务背景 
学术成果是指系统的、专门的或在学科化论证方面取得的成就与成绩，典型形态
包括发表于学术期刊或会议上的学术论文、授权的专利、主持的科研项目、所获得的
奖项等。学术成果来自高等院校、科研院所或高新企业等学术科研机构的科研从业人
员，其成果一般隶属于其所在科研机构。随着国家对科技创新的日益重视，学术成果
正成为日益宝贵的企业与社会资源，如何有效实现学术成果分享并推动科研合作，已
成为科学技术领域的热门话题。 
本项目定位建设一套面向广大科研从业人员的学术成果分享平台。该平台由专门
的管理机构运行和维护， 按照不同的学术领域分类管理学术成果，同时为认证通过的
科研从业人员建立个人门户系统，以维护个人学术成果。其基本的运行和管理机制包
括以下几个方面： 
（1）通过公共数据库、网络爬取等多种手段获得科研人员和其对应的学术成果 ，
经过相应的数据处理和清洗后，  建立系统的基础成果数据库。同时，为保证数据的时
效性 ，应考虑一定的数据更新机制，根据数据的特点， 建立相应的更新策略。 
（2）学术成果按照学术领域分类管理，提供分类过滤和检索功能。此外，学术成
果还应以成果的所有人（即科研人员）的视角统一展示，从而形式各科研人员的门户。
科研人员可以认领其门户，认领通过（需要建立一定的审核机制，保证是本人认领）
的可以管理其学术成果。门户系统应展示：科研人员的基本信息和专业技术领域等基
础内容， 以及其发表的所有的论文、科研项目、专利和获奖等学术成果 。 
（3）普通用户可以检索和查看系统内的各类科技人员信息、以及各类学术成果 。 
（4）系统应提供对科研人员、学术成果进行有效的统计和分析功能，实现诸如专
家关系网络、科研机构成果分类排名、科研领域热点分析等功能。 
（5）系统一期定位于学术成果的共享， 后期成熟后应考虑提供有偿增值服务，如
科技成果转让、论文全文下载和专利转让等业务功能。 
本实践任务要求在华为云 CodeArts 平台环境中，以规范的软件工程流程完成该平
台的需求调研、 需求分析、架构 及构件设计、编码实现、测试与部署，并系统性实践
当前前沿的 Agentic Coding 技术。

三、Agentic Coding 实践要求 
将当前 Agentic Coding 前沿技术纳入课程实践。以下内容须在最终答辩中展示完
整证据。 
（一）规范驱动开发（SDD） 
1. 编码前为每个核心模块编写开发规范（SPEC）：做什么（功能）、怎么做（接
口/算法/约束）、做到什么程度（验收标准），重点覆盖数据清洗规则、去重与消歧算
法、检索排序规则等数据密集型逻辑； 
2. 规范先行、代码履约：要求 Agent 生成代码前必须先存在对应规范，规范纳入
版本管理； 
3. 规范评审记录存档。 
交付证据：SPEC 文档目录、规范—代码对应关系表。 
（二）项目上下文文件（AGENTS.md） 
在仓库根目录建立 AGENTS.md，记录常用命令、架构概览、数据流、团队约定
与关键约束，并保持精简；作为 Agent 的长期项目记忆。 
交付证据：AGENTS.md 文件及内容说明。 
（三）CodeArts 代码智能体深度应用 
1. 使用代码智能体完成 5 类任务：项目级代码生成、代码续写、代码解释、单元
测试、调试自愈/代码修复； 
2. 对 AI 生成代码进行人工审查与修改，记录“AI 生成→人工修正”关键案例至少 3
个； 
3. 总结代码智能体的能力边界与失效模式。 
交付证据：AI 使用日志、修正案例记录。

（四）上下文工程与防御性提示 
1. 控制 Agent 上下文，规避上下文污染、上下文分心、上下文混乱、上下文冲突
四种失败模式； 
2. 采用防御性提示编写规范：精确（说清“怎么做”）、预判依赖、设置人工检查点、
使用强类型； 
3. 对预计超过 1 小时的 Agent 长任务设置人工确认检查点。 
交付证据：规范文档中的防御性设计说明。 
（五）AI 辅助测试与代码审查 
1. 使用 AI 生成单元测试用例，核心模块（清洗规则、消歧算法、检索排序、统计
计算）行覆盖率不低于 80%的模块不少于 3 个； 
2. 代码审查遵循“AI Gold Zone ／Human Zone” 分工：简单 bug、性能、安全与风
格由 AI 审查负责，业务逻辑与关键决策由人工审查负责； 
3. 记录 AI 审查与人工审查的对比结论。 
交付证据：测试报告、审查记录。 
（六）提示词资产管理 
1. 所有用于开发的提示词与规范模板纳入版本管理（prompt 即源码）； 
2. 建立提示词资产清单：用途、版本、效果评估。 
交付证据：提示词资产清单。
