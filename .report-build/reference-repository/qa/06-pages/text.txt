1.3 对本项目的启示 
由上述机制可以提出三个产品判断。第一，个人门户应具有持续维护和反馈能力，不
能仅是采集结果的静态页面。第二，自动关联提高资料组织效率，但需要允许修正，并解
释关键归属的依据。第三，图表分析的基础是经过合理组织的成果和关系，不能先追求展
示复杂度，再补数据解释。 
这些结论属于对公开产品机制的归纳，不等同于证明目标用户更偏好某一种交互方案。
具体页面布局、默认排序和操作文案仍可通过原型任务走查迭代。

2.9 采集和公开使用的项目约束 
仅采集已登记且允许使用的来源，不绕过登录、验证码或付费限制，不采集未授权私
人字段，不托管未获授权全文。元数据、摘要、原始附件和全文链接分别登记用途与访问
范围；公开可见的资料仍需核对再发布条件。认领证明存于私有审核空间，与公开成果数
据分开保存。具体来源条款在启用前核对。

3.1 场景走查的综合结果 
八个场景覆盖资料发现、个人展示、成果维护、统计查看、科研资料整理和错误反馈。
检索让成果可被发现，门户提供人员视角，认领和纠错完善关联，统计使用确认后的成果
关系；用户在查询和统计中发现的问题，再交由管理员处理。 
业务流程可概括为：资料形成 → 用户发现 → 人员确认 → 公开分享 → 统计观察 
→ 问题反馈 → 资料修正。后续通过原型走查和可用性测试检验这一流程。
