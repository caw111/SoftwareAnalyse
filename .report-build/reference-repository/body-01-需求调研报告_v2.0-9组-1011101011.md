
## 1. 引言

### 1.1 项目背景

学术成果检索与分享平台面向普通用户、科研人员和平台管理员，将论文、授权专利、科研项目和学术获奖组织为可检索的成果目录，并为科研人员提供公开门户。用户可以从研究主题、人员、机构或成果类型查找资料；科研人员可以申请门户管理权、确认本人贡献并纠正错误关联；管理员负责来源接入、身份审核和数据质量维护。

已有学术资料分散在论文题录、专利公告、项目清单与奖励目录中。不同来源的人员角色、编号和时间含义不完全相同，同名作者、重复收录与缺失字段也会影响展示和统计。本项目需要在方便发现资料的同时，保留来源依据，明确个人说明与公共事实的维护责任。

### 1.2 调研目的

本次调研为一期范围界定和需求建模提供依据，重点回答以下问题。

- 三类用户分别需要完成哪些任务，在哪些环节需要相互协作？
- 四类成果如何统一检索，又如何保留各自的人员角色、标识和时间含义？
- 自动收录之后，怎样确认门户管理权、处理错误归属并保持公开资料可信？
- 数据源、领域分类和统计口径能够支持哪些业务，哪些能力仍需真实样本验证？
- 一期应优先交付哪些功能，哪些功能应保留为增强或后续建设？

### 1.3 调研方法

本组现有材料采用任务书分析、公开资料研究、同类平台比较、角色任务分析、场景走查和已有实验记录审阅。未实施真实访谈或问卷调查，现有结论不能解释为目标用户群体的偏好统计。资料中记载的两项采集实验尚缺原始脚本、响应、样本和校验文件，本版保留其线索及限制。

| 调研方法 | 执行内容 | 形成的依据 |
| --- | --- | --- |
| 任务书分析 | 提取三类角色、四类成果、检索门户、认领审核、统计及治理要求 | 业务范围与课程约束 |
| 公开资料与竞品比较 | 审阅 Google Scholar、Semantic Scholar、OpenAlex、DBLP、ORCID 等平台机制 | 发现路径、身份与元数据治理做法 |
| 角色任务与场景走查 | 推演查询、认领、补录纠错、统计解释和更新失败处理 | 角色诉求、异常分支与权限边界 |
| 数据条件与实验记录审阅 | 整理 Crossref 定向题录和非论文公开清单的现有记录 | 来源可用性、字段差异及待复核事项 |
| 模型交叉核对 | 对照当前 images 中的 Draw.io 与 PNG，核对动作、状态和对象关系 | 图文一致性与缺图清单 |

### 1.4 报告结构

第 2 章说明调研过程与发现，第 3 章整合三类用户的核心场景、功能性和非功能性需求，第 4 章界定一期范围与优先级，第 5 章给出结论和后续工作，第 6 章列出实际附件。详细来源记录与证据追踪保存在调研材料中，SRS 将这些结论转化为用例规约，SPEC 规定核心模块处理规则。

## 2. 调研过程与发现

### 2.1 调查问卷分析

当前没有本组问卷发放记录、有效样本或受访者回答，因而本节不报告回收数量、比例或平均分。既有角色材料和公开平台机制用于提出待验证的需求假设，不能代替真实用户调查。后续调研应覆盖普通用户、科研人员和管理员，记录任务实例、现有做法、困难和功能取舍。

#### 2.1.1 核心发现

现有资料和场景走查支持以下建设方向。

- 成果发现与人员识别需要衔接。用户找到成果后，还要核对作者、机构、时间及来源；同名人员需要先作为候选展示，确认身份后再按人物标识查询。
- 自动汇聚需要持续治理。来源收录并不等于本人认可，平台需要保留重复候选、来源冲突和缺失字段，并提供反馈与审核路径。
- 门户管理权与成果贡献应分别确认。获得门户管理权不会自动认领所有候选成果，也不能改变合著者的有效关联。
- 四类成果可以共享检索和展示入口，但专利申请人、项目负责人、获奖单位等角色不能统一改称论文作者。
- 统计结果需要说明范围和计算依据。机构排名、领域热点及共著网络必须能够追溯至同一筛选范围内的成果。

#### 2.1.2 局限性分析

上述发现来自任务书、公开说明与情景推演，尚不能说明本校用户的实际任务频次、可接受审核时长、材料提交意愿或付费意愿。平台公开帮助页可以支持机制比较，但不能证明本组的用户偏好或系统性能。采集实验原件未补齐前，来源稳定性、全库完整率和算法准确率仍需复核。

### 2.2 竞品分析

本次比较围绕检索发现、学者门户、身份标识、元数据组织和成果纠错展开。各平台的适用范围不同，本组借鉴业务机制，不根据品牌知名度推定其数据完全准确或可以无限制抓取。

| 比较对象 | 可借鉴的机制 | 本平台的需求取舍 |
| --- | --- | --- |
| Google Scholar Profiles | 人员视角组织论文，允许维护个人资料与修正记录 | 提供公开门户与错误反馈，仍需支持四类成果和审核边界 |
| Semantic Scholar | 来源形成作者页面，提供认领及作者资料纠错渠道 | 来源人物、平台账号、门户授权分开建模 |
| OpenAlex | 成果、作者、机构与主题的关联组织 | 候选规模来源与分类补充，启用前核验映射和访问条件 |
| DBLP | 计算机学科书目与作者组织 | 专业题录补充，不推定摘要、机构与开放状态均完整 |
| ORCID | 稳定人员标识与授权交互 | 支持有依据的身份核对，手填标识不等于本人控制证明 |
| Crossref 与 Unpaywall | DOI 元数据、出版来源及开放获取入口 | 题录、分类和全文获取分别处理，查询失败与无可用数据分开提示 |

#### 2.2.1 核心洞察

平台的建设重点是将资料发现、人员门户和持续治理连接起来。自动采集降低重复录入成本，来源追踪帮助核对资料，人工审核处理自动规则无法确认的身份与归属，统计解释则避免将收录数量误当作完整科研评价。私人笔记和资料导出可以提高使用效率，但应与公共成果事实分开保存。

### 2.3 原型法应用

当前没有可交互产品原型或用户可用性测试记录，本版不声明已经完成原型验证。现有用例图、活动图、状态图、类图和检索时序图用于团队内部走查，检查条件分支、角色交接及失败处理。

查询走查覆盖主题或标识查询、同名学者确认、组合筛选、空结果和超时恢复。认领走查按当前编号 03 与 04 模型，覆盖校验失败、补充材料、绑定竞争、驳回和撤回。研究现状走查覆盖纳入与排除理由、资源受限状态、原文定位、统计比较和资料导出。后续可用性验证需记录参与对象、任务、观察结果与修改依据。

### 2.4 数据源与领域分类调查

论文以 Crossref 的 DOI 或 ISSN 定向题录链路为已记录线索，OpenAlex 与 DBLP 为规模和专业补充候选。专利、项目和获奖分别审阅公开公告或清单。当前材料记载了 HTTP 412、网页应用外壳、缺少授权日期及公告时间与成果时间不同等情况，不能据公开入口存在宣称已经完成通用接入。

| 成果类型 | 候选或已记录来源 | 必须保留的差异 |
| --- | --- | --- |
| 论文 | Crossref、OpenAlex、DBLP；Unpaywall 辅助开放状态 | DOI、出版日期含义、来源作者和可获得的开放入口 |
| 授权专利 | 知识产权公开服务、正式授权公告或高校公开清单 | 申请号、公开号、文献阶段、授权证据、发明人与申请人 |
| 科研项目 | 基金委或其他资助机构公开公告与清单 | 资助机构和项目编号、负责人、依托单位、资助年度与立项时间 |
| 学术获奖 | 科技部及其他正式授奖目录 | 授奖机构、奖励年度、奖项等级、完成人或获奖单位 |

领域分类采用稳定的本地学科组织方式与来源主题标签并存的方案，保留分类来源、版本和确认状态。采集范围不自动等于学科分类；无法映射的资料保持未分类，多领域成果允许多重归属并在统计时解释。数据源清单、两项实验记载及限制详见附件。

## 3. 需求分析与整合

### 3.1 用户画像与核心场景

以下画像代表角色任务组合，是本组用于分析的情景模型，并非真实受访者或调查样本。

**普通用户。** 目标是找到并核实研究资料。用户从主题、人物、机构或成果编号进入，逐步筛选范围，确认同名人物，查看成果详情和原始来源，并根据同一条件查看统计明细。主要中断点是类型混杂、身份歧义、字段缺失以及外部入口不可用。

**科研人员。** 目标是整理本人可信门户并利用研究资料。用户先完成必要身份审核，再选择门户提交认领证据；审核及唯一绑定成功后维护本人说明，逐项确认贡献、补录或纠正遗漏。开展研究现状调研时，需要保存专题、笔记、纳入理由和原文定位，研究结论仍由本人形成。

**平台管理员。** 目标是保持公共资料与处理过程可复查。管理员配置来源与采集任务，处理身份、门户、成果和机构请求，核对重复候选与字段冲突，记录理由并更新检索和统计版本。其后台角色不自动取得他人的私人笔记或未授权材料访问权。

## 4. 项目范围与功能优先级

### 4.1 核心价值主张

平台以公开学术资料为基础，将多类型成果发现、人员门户、归属确认和数据治理连接为持续过程。其价值在于让用户能找到资料、核对依据、维护正确关联，并理解所见统计的范围。论文承担主要真实数据规模，专利、项目和获奖保持各自的基础收录、查询、管理和统计路径。

### 4.2 一期项目范围界定

**纳入范围。** 四类成果的基础流程，公开成果与学者检索，门户认领与审核，成果确认、补录、纠错与反馈，来源与质量追踪，基础统计，共著网络与拟定最短路径创新，以及来源任务、索引和统计更新。身份审核、门户管理权和具体成果贡献分别处理。

**排除范围。** 成果交易、支付、未经授权全文托管、付费墙绕过、完整商业引文库替代、正式科研综合评价。讨论订阅、高级预测、复杂关系指标与机构 SSO 保留为后续功能。P1 收藏、专题笔记、导出和相关推荐按团队实现及验证能力启用。

### 4.3 功能优先级列表

- P0：四类成果、来源清洗去重、公开检索门户、认领审核、维护纠错、基础统计、共著证据、来源任务与恢复；最短共著路径为拟定一期创新。
- P1：私人收藏与保存检索、关注、专题笔记、资料比较与导出、可解释相关推荐。
- P2：讨论订阅、个性化、复杂网络指标与预测、机构 SSO 等后续功能。

实现次序为准备四类样本及来源依据，贯通公开查询与认领治理，再建立同范围统计和网络证据，随后扩充论文规模并验证异常恢复。优先级不能用于删减课程要求的基础业务。

## 5. 结论与后续工作

### 5.1 结论

现有调研材料可以支持课程项目的初步角色划分、业务范围和规则选择。四类成果应共享发现入口，账号、学者、门户授权与成果贡献应分离，自动汇聚后的纠错和更新应保留来源及处理历史，统计应能够回到支撑成果核对。真实用户需求与技术指标仍需通过调查、原件复核和固定测试集确认。

### 5.2 后续工作建议

- 补齐三类角色的任务走查或访谈记录，确认材料提交、审核等待和结果解释是否适用。
- 补齐两项来源实验的脚本、原始响应、样本和校验文件，验证访问方式及字段映射。
- 用当前 Draw.io 模型检查申请、停止、查询与恢复分支，补齐缺图和可编辑源文件。
- 将调研发现追踪到 SRS 的用例包、FR 条目、SPEC 模块和 AC 场景，记录范围或规则变更。
- 课堂展示后记录教师与互评意见、修改人、日期与验证结果，完成真实的人工审查及 AI 使用确认。
