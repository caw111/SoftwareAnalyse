## 1. 调研目标与方法

### 1.1 项目背景

甲方任务书将平台定位为面向科研从业人员的学术成果分享平台：通过公开来源获得科研人员及其成果，按照学术领域组织信息，为通过审核的科研人员提供个人门户，并支持检索、成果维护和统计分析。成果范围包括论文、授权专利、科研项目和获奖。[A1]

这一定位包含两方面业务。一方面，普通用户需要从成果中寻找研究资料，并进一步了解作者、机构和研究方向；另一方面，科研人员及管理员需要共同维护成果归属与信息质量。前者决定平台的发现能力，后者决定公开展示能否被信任。

如果仅建设论文搜索入口，人员门户、其他类型成果和治理流程容易缺位；如果一开始追求完整学术评价和商业化交易，又会超出课程项目可控制的范围。调研需要在业务覆盖与实施工作量之间形成有依据的取舍。

### 1.2 调研问题

本次调研围绕以下问题展开：

1. 普通用户、科研人员和管理员分别需要完成什么任务，彼此在哪些环节发生协作？
2. 成果信息分散、作者同名、记录重复和归属不清会怎样影响这些任务？
3. 同类平台如何处理个人主页、成果补充、错误关联和信息更新？
4. 四类成果有哪些共同的组织方式，又有哪些必须保留的差异？
5. 机构排名、领域热点和合作网络分别能回答什么问题，其解释边界在哪里？
6. 公开数据能支撑哪些业务，哪些环节需要人工审核或辅助来源？
7. 一期应优先形成哪些业务能力，哪些能力适合后续建设？

### 1.3 方法与材料范围

调研采用公开资料研究和业务场景推演，未开展实地访谈或问卷调查。角色模型与案例用于分析任务和异常流程。

| 角色与任务分析 | 从各角色的目标、输入、判断和协作关系推演需求 | 角色模型、关注点及冲突分析 |
| 典型场景推演 | 对检索、认领、维护、统计和异常处理进行逐步走查 | 业务场景及中断点分析 |
| 数据条件调查 | 核对论文及非论文成果的公开来源和信息范围 | 数据支撑能力、来源限制与可行性判断 |

## 2. 场景走查记录

本节案例为情景推演，用于检查正常路径、异常路径和角色交接，不是受访者经历或实测操作记录。

### 2.1 场景一：围绕研究主题寻找成果与人员

**任务背景：** 一位用户需要了解某个研究方向，掌握近年的相关成果，并找到继续跟踪的科研人员。

**推演路径：** 从主题检索进入候选成果，按年份与领域缩小范围，阅读详情，核对来源和作者，进入人员门户，再查看相关成果或合作关系。

**中断点：** 作者同名导致进入错误门户；同一成果重复出现；只有题名但缺少来源；外部访问入口与用户对全文的期待不一致。

**分析结论：** 检索、详情、人员门户和关系线索应构成连续的发现过程。系统需要帮助用户逐步核对，而不只是增加结果数量。

### 2.2 场景二：科研人员整理并认领自己的门户

**任务背景：** 平台已有从公开资料形成的候选门户，其中既可能漏收成果，也可能混入同名人员资料。

**推演路径：** 科研人员确认身份并找到候选门户，提供认领依据；管理员核验后授予管理权；科研人员检查候选成果，确认真实关联并反馈错误项。

**中断点：** 同名门户无法区分；机构认证通过后即被错误授予门户；拥有门户管理权被误解为自动确认其中所有候选成果。

**分析结论：** 身份确认、门户认领和具体成果关联是三个不同判断。分开处理能解释每一步授权的依据，也便于在错误发生时定位责任。

### 2.3 场景三：补充未收录的项目、专利或获奖

**任务背景：** 科研人员的部分贡献来自非论文成果，公共库中尚未收录。

**推演路径：** 先检索是否已有对应成果；不存在时按类型整理资料与来源；管理员核对身份、成果标识和重复情况；确认后公开展示，并与个人门户关联。

**中断点：** 用论文格式描述所有成果，造成项目负责人、专利发明人和获奖完成人的含义混淆；同一成果因多人分别提交而重复入库。

**分析结论：** 应统一组织不同成果，保留类型差异，并优先复用已有记录。补录是资料形成的一条受治理路径，而非绕过审核的直接发布。

### 2.4 场景四：纠正误归属且保留其他人的成果

**任务背景：** 某人发现一篇合著论文与本人错误关联，其他作者的关联则正确。

**推演路径：** 提出撤销本人关联的申请；管理员核验；撤销错误关系并保留共享成果及其他作者关联；相关个人统计随数据变化更新。

**中断点：** 将“从我的列表移除”实现为“从公共库删除”，从而影响其他作者和平台总量。

**分析结论：** 人员与成果之间的关联、公共成果记录是不同治理对象。错误修正需要限定影响范围，并同步公开展示与统计。

### 2.5 场景五：理解机构分类排名和领域热点

**任务背景：** 用户希望比较某一领域中不同机构的成果分布，并了解主题随时间的变化。

**推演路径：** 明确机构、领域、年份和成果类型范围；查看统计结果；了解数据覆盖情况；对感兴趣的数量或主题回到对应成果进行核对。

**中断点：** 未注明收录范围却展示“机构排名”；合著成果重复计数；当前机构替代成果发生时机构；最新年度尚未结束却直接按全年比较。

**分析结论：** 统计分析首先应具有可解释性和可追溯性。机构数量、研究热点与合作网络提供不同观察角度，不宜压缩为一个未经论证的综合分数。

### 2.6 场景六：管理员处理来源更新失败

**任务背景：** 数据源暂时不可用，或者新采集的信息与既有记录冲突。

**推演路径：** 管理员识别异常及影响范围，保留可用旧资料；对可恢复失败重新处理，对冲突进入核验；向相关申请者反馈处理状态。

**中断点：** 将“申请已通过”显示为“数据已入库”；失败后不保留原因；部分更新使门户与统计表达不同事实。

**分析结论：** 收到申请、审核决策和资料完成更新是不同业务结果。平台需要把信息流转状态与最终交付结果分开表达。

### 2.7 场景七 研究现状调研与资料整理

研究生按主题和近五年范围检索，确认作者与论文出处后，查看已收录的参考关系、代码和数据集入口。他可以在专题库记录研究方法、实验条件、资源版本、局限和原文位置，选择 2 至 10 篇论文比较并导出引用。比较页面应注明资源缺失和条件差异，研究结论由用户判断。专题与比较功能列为 P1。

### 2.8 场景八 查询恢复与数据反馈

匿名用户从结果列表进入详情或作者门户后返回，系统保留人物、筛选条件、排序和浏览位置；登录收藏后也可继续原任务。无结果、参数错误和超时分别提示。用户发现错误关联或失效链接时，可以提交对象、理由和公开证据，并获得受理编号；公共字段的修改由管理员审核。
