# 参考文档格式与重构约定

## 参考依据

用户指定 GitHub 仓库的 dev 分支 docs/01.需求调研/需求调研报告 PDF 和 docs/02.需求建模/系统需求规格说明书 PDF。参考文件、下载元信息和逐页文字保存在本目录；样式核对截图为 research-page-* 与 srs-page-*。原 PDF 不修改，不作为本组工作成果提交。

## 页面与排版

- A4 纵向，约 595.3 × 841.9 pt。
- 表格与页眉横线约从 x=72 到 x=523 pt，左右边距约 2.54 cm。
- 正文段落与标题起点约 x=90 pt，即相对版心左缩进约 18 pt；正文首行再缩进约 21 pt。
- 正文宋体约 10.5 pt，拉丁字符 Times New Roman；正文行距约 15.6 pt。
- 一级标题居中约 16 pt；二级标题左对齐约 14 pt；三级约 12 pt；用例标题约 10.5 pt。标题均黑色。
- 封面课程名称约 14 pt，项目名称约 26 pt，文档名称约 24 pt，均居中；封面含小组编号、小组名称、小组联系人三项成员信息表，末尾年份使用本组当前的 2026 年。
- 封面后为单独版本变更历史页，五列表头为版本、提交日期、主要编制人、审核人、版本说明。
- 再后为独立目录页，页码使用罗马数字；正文页码从阿拉伯数字 1 开始。
- 正文页眉为课程及文档名称、下方黑色细横线；页脚居中页码。表格白底、黑色细网格，无彩色表头或交替底纹。

## 内容结构

调研报告采用六章：引言；调研过程与发现；需求分析与整合；项目范围与功能优先级；结论与后续工作；附件清单。沿用已有公开资料、场景与数据源记录，未实施的问卷及原型测试如实标明。

SRS 采用四章：引言；系统参与者；系统用例模型；补充规约。用例分五包：用户与认证服务、学术信息服务、学术门户管理、科研态势分析、平台运营与数据维护。每份用例表包括用例名称、简要描述、参与者、涉众、前置条件、成功和失败后置条件、基本路径及备选路径；已有对应图在表内或紧随表后引用。

SPEC 沿用原核心规则与编号，采用相同封面、版本、目录和正文视觉格式；参考仓库没有独立 SPEC PDF，不能声称其模块目录来自参考仓库。

## 保留与一致性

保留四类成果、三类角色、P0/P1/P2 边界、六状态门户认领、SUCCEEDED 采集成功与 STOPPED 重试耗尽规则，保留 FR、AC、SPEC 编号及原验收目标。以新 UC1.x 至 UC5.x 组织用例，并另给旧编号映射与完整需求、验收支撑材料。

只能采用当前根目录 images 中能找到的图和 Draw.io 文件，不复制参考仓库的模型图片；缺图继续单列。参考报告的问卷数量、百分比、用户访谈、原型成果和模型选型不当作本组已完成的事实。

最终 Submit 仍按作业1和作业2分别打包，Word 为正文，Markdown 为源稿；调研支撑、模型、PPT、修改记录、AI 声明及自查清单分别保留。旧稿保存到历史归档，已有未关闭 Word 文件不强制关闭或丢弃用户编辑。
