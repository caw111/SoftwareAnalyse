## 2. 从场景归纳的输入契约

| 输入 | 已确认规则与模型处理 |
|---|---|
| query | 普通关键词；空关键词有筛选可浏览；全空按明确的最新收录顺序。不能把所有含斜杠的普通词误判成非法DOI |
| type | 论文、专利、科研项目、学术获奖；`all`默认按类型分组，不直接混比各索引原始分 |
| 人物 | 先按姓名返回不同候选，再传确认的内部人物ID；ORCID定位人物不证明账号控制 |
| person_mode | `any`：至少一位选定人物满足；`all`：每位选定人物都满足。显式保留，不套用普通维度OR覆盖all |
| 机构与author_scope | 按成果发生时机构关系；指定人+机构必须验证贡献关系，不能将人物集合和机构集合独立相交。`same_contribution`按同一贡献元组核验。`any_contribution`的精确定义在正文不足，见TODO-B5-01，暂不宣称该分支已定稿 |
| 领域 | 领域ID、是否包含子领域及分类树版本；未知分类保留明确状态 |
| 时间 | 起止及精度合法；论文出版、专利授权、项目资助、奖励年度按类型解释，立项等专属字段须明示；来源公告日不替代业务年 |
| 来源/模拟 | 可筛选来源和真实/模拟范围；返回与统计明细传递同一范围，不混报模拟验收 |
| sort | 默认有效配置的文本相关度；并列按业务年降序、未知后置、规范成果ID升序。日期排序按声明日期再相关度/ID；引用排序固定同一来源观察，缺失后置 |
| page/page_size | 对外统一SPEC蛇形字段`page_size`（任务书pageSize为同义说明）；默认10，1～100。正整数页码，实际越界需总数返回后再判定。空集合page=1是有效空，page>1按越界处理；该边界约定待B1确认 |
| releaseId | 首次未指定才绑定当前可用版；翻页、详情、返回与统计明细沿用原版；失效后用户显式刷新才重新绑定 |

跨维度AND，同维度多选OR，人物集合遵循显式all/any。精确合法DOI、公开号、项目号优先定位相应类型；项目号结合资助机构/批准计划消歧，歧义先提示。ORCID/ROR定位实体，不触发认领。不能将格式不合法的标识自动改写为另一个成果；仅对用户明确声明或可识别的标识输入报告标识错误。

**贡献匹配谓词示例（分析表达式，不是实现代码）：** 设成果w的贡献元组为C(w)，选择人物P、机构集合O。`match(p,w) := 存在c∈C(w)，c.personId=p 且 c.orgIds与O有交集`（未筛机构时省略机构项）。`any`取存在p，`all`取每个p。例：w只有(S1,O1)、(S2,O2)，查S1+O2应不命中；查S1+O1应命中。这一示例只定义已明确的同贡献范围，不替`any_contribution`创设新义。

## 3. 生命线与归纳出的职责

| ID | 生命线 | UML角色 | 职责 | 与业务类图交接 |
|---|---|---|---|---|
| L1 | 访客/检索用户 | actor | 发起公开查询和详情访问 | 参与者不强制对应Account实例 |
| L2 | SearchPage 检索页面 | boundary | 输入、呈现、错误说明、恢复上下文 | 边界对象不要求进核心业务类图 |
| L3 | SearchControl 检索控制对象 | control | 校验、协调版本/检索/读取/权限 | 分析控制职责，不据此机械新增领域实体 |
| L4 | PublicRelease 公开版本契约 | entity/查询契约 | 固定范围、索引、规则、分类、统计构建版本及可用性 | 可作为发布值对象/契约，交B2选择最终表达 |
| L5 | SearchIndex 检索索引服务 | control | 同版过滤、有效配置排序、稳定分页 | 可重建技术服务；不冒充权威Work |
| L6 | PublicWorkReader 公开成果读取对象 | control | 同版读取Work类型字段、Contribution、来源与缺失 | 背后须有Work、四子类、Scholar、Institution、领域、SourceRecord及贡献关系 |
| L7 | VisibilityPolicy 当前权限策略 | control | 当前对象/字段可见性；管理动作单独查有效授权 | 策略不是新增认领状态；Account、Scholar、PortalAuthorization、Contribution分离 |

从消息归纳的候选职责为`PublicRelease.resolve/requireAvailable`、`SearchIndex.execute`、`PublicWorkReader.readPublic`、`VisibilityPolicy.checkCurrent`。这些是分析命名，尚未得到B2命名表确认；不强制将所有服务加进业务类图。检索只读，既不创建管理授权，也不把来源人物变成账号。

## 5. 组合片段、异常结果与不变量

| 片段 | 互斥分支和覆盖 | 状态/结果 |
|---|---|---|
| F01 alt | 非法或需确认 / 合法且语义确定 | 错误与候选提示不混同；无业务状态写入 |
| F02 alt | 指定版失效 / 无可用版 / 固定版有效 | 版本失效、服务错误、继续同版 |
| F03 alt | 服务超时失败 / 版本异常 / 成功同版 | 错误不生成伪空结果；两类同时出现时先报告已确定的执行错误 |
| F04 alt | 根据实际总数越界 / 有效页 | 不在索引返回前猜测最后页 |
| F05 opt | 存在ID才读详情；空集合跳过 | total=0不调用空ID详情；仍复核当前权限范围 |
| F06 alt | 读取/校验失败 / 当前范围变化 / 均通过 | 失败优先，不返回不完整成功；范围变化提示重试 |
| F07 alt | total=0 / total>0 | 空与有结果均是成功语义 |
| F08 opt/ref | 仅有结果且用户选择详情 | 子图每次检查原版与当前权限 |

非法输入（包括明确非法DOI）返回字段/标识错误；有效精确标识无匹配是合法空结果；同名未确认返回候选而不合并；索引或详情超时是可重试错误；版本被清理是失效，不能静默回退；同版记录缺失是明确读取/一致性错误，不能靠当前库补齐。HTTP 410/422/503等仅沿用SPEC §11的候选映射，不把它们当已定接口。

列表与详情仅允许公开字段投影。认领证明、私有申请、私人笔记从不作为公开卡片字段；登录用户也不能凭查询版本恢复已撤销管理权限。公开资料读取和门户管理按钮权限分开判断。

**关于总数与权限：** 不能先以旧索引取总数，再只删当前页受限项，仍声称结果完整。本设计先传当前公开范围，返回前校验范围标记；发生影响命中集合的变化就返回可重试的“可见范围变化”，不返回旧总数。如何实现一致性边界/令牌以及是否采用这项保守策略留待B1/B2评审；这不是SRS新增业务状态，也未声称实现了无竞态的软件。
