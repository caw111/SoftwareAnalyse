《软件系统分析与设计》课程实践（一）
学术成果分享平台
数据源调研与数据密集型逻辑规范
版本：V1.0调研日期：2026年9月26日适用阶段：需求调研、需求建模、核心模块 SPEC 编制

1. 文档目的与调研范围
本文件服务于“学术成果分享平台”的需求调研与需求建模阶段。文件围绕论文、专利、科技奖励三类学术成果建立数据源方案，并形成能够直接进入后续系统设计与开发阶段的数据采集、字段标准化、数据清洗、重复记录识别、实体消歧、冲突处理、增量更新和检索排序规则。项目任务书要求平台能够通过公共数据库和公开网络来源获得科研人员及其学术成果，并且要求系统建立数据清洗、去重、消歧、增量更新、全文检索和统计分析能力。
本次调研将数据来源划分为主数据源、补充数据源和身份标识数据源。系统对每一条原始记录保存来源信息、来源记录标识、采集时间和原始内容摘要，并在规范化处理以后形成统一成果记录。系统保留各来源之间的差异信息，使后续数据更正、来源追踪和审核工作具有完整依据。
1.1 调研对象
论文及其作者、机构、期刊或会议、引用关系、研究主题等元数据。
专利及其申请号、公开号、申请人、发明人、分类号、同族、法律状态等元数据。
国家级、省部级和全国性学会科技奖励及其项目名称、奖项类别、等级、年度、完成单位、完成人等元数据。
作者身份标识和科研机构身份标识，用于作者消歧与机构消歧。
1.2 设计原则
统一标识优先原则。DOI、ORCID、ROR、专利公开号、专利申请号等标准标识具有最高匹配优先级。
来源可追踪原则。规范化记录需要保留来源名称、来源记录标识、原始字段值、采集时间和处理版本。
字段级冲突管理原则。系统按照字段分别选择权威来源，引用次数等来源口径不同的数据按照来源分别保存。
自动处理与人工复核分级原则。系统为确定性匹配设置自动合并阈值，为中间置信区间建立人工复核队列。
原始数据保留原则。系统在数据清洗和合并期间保留原始记录，规范化记录通过关联关系指向原始记录。
合规采集原则。系统优先采用公开 API、公开数据下载文件和官方公开页面，并遵循各平台的许可协议、访问频率要求和版权要求。

OpenAlex 可以承担论文主数据源。OpenAlex 提供面向科研成果、作者和机构的综合索引，并且提供 API 和数据快照。DBLP 可以承担计算机领域补充数据源。DBLP 提供论文、作者和期刊会议检索接口，并且提供完整 XML 数据文件。Crossref 可以承担 DOI 元数据校验源，其公开 REST API 提供 DOI 相关的出版元数据、基金信息、许可信息、ORCID 和 ROR 等标识。OpenCitations 可以承担引用关系补充源。ORCID 和 ROR 分别承担研究人员与机构的标准身份标识补充工作。

2.2.1 专利记录的两个层次
系统需要同时维护“专利公开记录”和“专利家族”两个层次。一个发明可能在多个国家或地区形成多个公开记录，同一申请也可能形成不同公开阶段的文献。系统以“主管机构代码 + 公开号 + 文献种类代码”识别具体公开文献，并以专利家族标识建立不同国家或地区记录之间的关联。检索结果页面可以按照用户选择展示具体公开文献或折叠后的专利家族。

科技奖励数据具有来源分散、页面结构差异较大、历史页面格式变化明显的特征。系统需要按照授奖机构分别建立采集适配器。国家级奖励优先采用国家科学技术奖励工作办公室和科学技术部公布的获奖目录。学会奖励采用授奖学会的官方获奖公告和历年获奖目录。省部级奖励采用相应省级科技管理部门或者其他正式授奖部门公布的结果。

3. 统一数据接入与来源追踪方案
系统的数据处理链路统一设置为：原始采集、结构解析、字段标准化、候选重复检索、重复判定、实体消歧、字段合并、质量校验、正式入库、搜索索引更新。每一个步骤生成处理状态和处理日志。
处理阶段 | 输入 | 主要处理 | 输出
原始采集 | API、XML、JSON、HTML、PDF 解析结果 | 保存来源记录标识、抓取时间、内容摘要和校验值 | raw_record
结构解析 | raw_record | 按照来源适配器映射字段 | source_record
字段标准化 | source_record | 标识符、文本、姓名、机构、日期和分类字段标准化 | normalized_record
候选重复检索 | normalized_record | 通过 DOI、公开号、题名指纹、作者等建立候选集合 | candidate_pairs
重复与消歧 | candidate_pairs | 精确规则与加权评分 | match_decision
字段合并 | match_decision | 按照字段来源优先级合并主记录 | canonical_record
质量校验 | canonical_record | 必填项、格式、范围、一致性校验 | quality_result
正式入库 | 通过校验的主记录 | 写入成果库和来源映射表 | production_data
索引更新 | production_data | 构建检索字段和聚合字段 | search_index

4. 数据清洗规则
以下规则作为 SPEC-DATA-01《数据清洗规范》的主体内容。所有清洗操作保留原始值，并且将规范化值写入独立字段。
4.1 通用文本清洗规则
规则编号 | 字段 | 处理规则 | 示例
CLN-TXT-01 | 全部文本 | 执行 Unicode NFC 规范化；统一不可见空白字符；连续空白压缩为一个半角空格；删除首尾空白 | “Deep  Learning ” → “Deep Learning”
CLN-TXT-02 | 比较用文本 | 生成独立的 normalized 字段；英文转换为小写；统一全角与半角字符；统一常见连接符和引号；保留展示字段原文 | “Graph-Based” → “graph-based”
CLN-TXT-03 | 题名 | 比较字段删除句末句号；统一 HTML 实体；保留数学公式和有语义作用的符号 | “A Study of X.” → “a study of x”
CLN-TXT-04 | 摘要 | 清理 HTML 标签和脚本内容；保留段落文本；记录原始来源许可信息 | HTML 摘要 → 纯文本摘要
CLN-TXT-05 | 关键词 | 分隔符统一；删除空项；按规范化形式去重；保留原始大小写的展示值 | AI; ai；LLM → AI, LLM

4.2 标识符清洗规则
规则编号 | 标识符 | 处理规则
CLN-ID-01 | DOI | 转换为小写；删除 doi:、https://doi.org/、http://dx.doi.org/ 等前缀；删除首尾空白；保存 DOI 主体
CLN-ID-02 | ORCID | 转换为标准 0000-0000-0000-0000 形式；执行校验位验证；验证失败的值进入异常队列
CLN-ID-03 | ROR | 统一保存完整 ROR 标识和规范 ID；机构主表建立唯一约束
CLN-ID-04 | ISSN | 去除多余空格；转换为 XXXX-XXXX 形式；执行校验位验证
CLN-ID-05 | 专利公开号 | 拆分国家或地区代码、公开号主体和文献种类代码；统一大写；删除展示空格
CLN-ID-06 | 专利申请号 | 按照来源国家或地区规则保存标准形式，同时保存原始形式

4.3 人员姓名清洗规则
规则编号 | 处理规则
CLN-PER-01 | 保存原始姓名、规范显示姓名和姓名比较键三个字段。
CLN-PER-02 | 英文姓名比较键统一字母大小写、标点和连续空格；姓名展示字段保留来源中的变音符号。
CLN-PER-03 | 中文姓名保留中文原名；拼音和英文写法作为别名保存；系统仅依据姓名字符串执行候选召回，实体合并需要结合身份标识、机构、合作者和成果等信息。
CLN-PER-04 | ORCID 经过认证绑定以后，将 ORCID 作为研究人员的强身份标识。
CLN-PER-05 | 作者顺序独立保存在成果—作者关系表中，任何姓名规范化处理均保持作者顺序。

4.4 机构名称清洗规则
规则编号 | 处理规则
CLN-ORG-01 | 保存来源机构名称、规范机构名称、机构别名、所在国家或地区和 ROR ID。
CLN-ORG-02 | 匹配 ROR ID 成功以后，规范机构名称采用 ROR 记录中的名称，本地来源名称进入机构别名表。
CLN-ORG-03 | 院系和实验室作为机构层级信息保存；学校或研究机构作为顶层科研机构实体保存。
CLN-ORG-04 | 历史名称和合并前机构名称通过别名关系关联到统一机构实体，同时保存有效时间范围。

4.5 日期、分类和数值字段清洗规则
字段 | 处理规则
日期 | 统一转换为 ISO 8601；仅有年份时保存 precision=year；仅有年月时保存 precision=month；完整日期保存 precision=day
引用次数 | 保存非负整数，并保存统计来源和统计时间；多个来源的引用次数分别存储
奖励等级 | 建立受控词表，例如特等奖、一等奖、二等奖、三等奖；来源中的其他表达通过映射表转换
奖励类别 | 按授奖机构的正式分类保存，并建立平台统一分类字段
CPC/IPC | 转换为大写规范形式；建立层级字段，支持按部、类、小类、组聚合
学术领域 | 保存来源领域标识和平台统一领域标识；建立来源分类到平台分类的映射表

4.6 缺失字段处理
来源中缺失的字段保存为空值，并且记录字段缺失状态。系统禁止使用推测值覆盖缺失字段。
其他可信来源能够提供同一实体字段时，系统按照字段来源优先级补充该字段，同时记录字段来源。
论文摘要、关键词、机构等可选字段的缺失不会阻止基础记录入库；DOI 缺失的论文通过题名、作者和出版信息进入去重流程。
奖励记录缺少统一标识时，系统生成内部 UUID，并通过授奖机构、年度、类别、等级、项目名称和完成人信息执行去重。
5. 重复记录识别算法
以下规则作为 SPEC-DATA-02《成果去重规范》的主体内容。系统将重复识别划分为精确匹配、候选召回、相似度评分和合并决策四个步骤。
5.1 论文去重算法
5.1.1 第一阶段：精确匹配
两个论文记录均具有合法 DOI，并且规范化 DOI 完全相同，系统直接判定为同一论文。
DBLP 来源记录具有相同 DBLP key 时，系统直接判定为同一来源记录。
OpenAlex 来源记录具有相同 OpenAlex Work ID 时，系统直接判定为同一来源记录。
5.1.2 第二阶段：无 DOI 或 DOI 缺失情况下的候选召回
系统为每篇论文生成题名指纹。题名指纹由规范化题名删除空白和弱标点以后生成。候选集合满足以下任一条件：
规范化题名完全相同。
题名字符三元组相似度达到 0.75，并且出版年份差值小于或等于 1。
第一作者规范姓名相同，并且题名词项 Jaccard 相似度达到 0.60。
5.1.3 第三阶段：候选对评分
论文候选对使用以下固定评分公式：
S_paper = 0.55×S_title + 0.20×S_author + 0.10×S_year + 0.10×S_venue + 0.05×S_pages
其中，S_title 为规范化题名字符三元组余弦相似度；S_author 为作者集合 Jaccard 相似度；S_year 在年份相同的时候取 1，年份相差 1 的时候取 0.5，其余情况取 0；S_venue 为期刊或会议规范标识匹配结果；S_pages 为起止页、文章号或电子文章编号匹配结果。
评分区间 | 处理结果
S_paper ≥ 0.92 | 自动合并为同一论文
0.82 ≤ S_paper < 0.92 | 进入人工复核队列
S_paper < 0.82 | 保留为独立论文记录

当两个记录同时存在合法 DOI 且 DOI 不同的时候，系统将两个记录保持为独立记录，并且创建“疑似版本关系”复核任务。预印本与正式出版版本通过 related_work 关系关联，系统保持两个成果记录。
5.2 专利去重与专利家族处理
具体专利公开文献以“主管机构代码 + 公开号 + 文献种类代码”作为首选唯一键。
来源平台省略文献种类代码的时候，系统使用“主管机构代码 + 公开号”进行候选匹配，并结合申请号和公开日期完成判定。
同一国家或地区的来源记录具有相同申请号，并且标题、申请日和申请人一致时，系统合并来源记录。
多个国家或地区针对同一发明形成的专利记录保持为独立公开记录，并通过专利家族实体关联。
EPO 提供的专利家族标识可以作为家族归并的重要依据；系统同时保存家族来源和家族类型。
同一专利在公开、授权等阶段形成不同文献种类代码时，系统保持公开文献记录，并通过同一申请实体建立阶段关系。
5.3 科技奖励去重算法
科技奖励缺少跨平台统一标识。系统生成以下复合匹配键：
K_award = 授奖机构规范ID + 奖项规范名称 + 获奖年度 + 奖励类别 + 奖励等级 + 规范化项目名称
复合匹配键完全一致时，系统直接判定为同一奖励记录。复合匹配键存在文本差异时，系统使用以下评分公式：
S_award = 0.50×S_project + 0.20×S_person + 0.15×S_org + 0.10×S_category + 0.05×S_year
S_project 为项目名称相似度；S_person 为主要完成人集合相似度；S_org 为主要完成单位集合相似度；S_category 为奖励类别和等级的一致性评分；S_year 为获奖年度一致性评分。
评分区间 | 处理结果
S_award ≥ 0.93 | 自动合并
0.84 ≤ S_award < 0.93 | 进入人工复核队列
S_award < 0.84 | 保留为独立记录

6. 作者与机构消歧算法
以下规则作为 SPEC-DATA-03《作者与机构消歧规范》的主体内容。
6.1 作者消歧
6.1.1 强标识匹配
两个作者记录具有同一经过校验的 ORCID iD 时，系统合并为同一研究人员实体。
同一来源中的稳定作者标识保持唯一映射，例如 OpenAlex Author ID 和 DBLP person 标识。
经过门户认领流程验证的研究人员账户与 ORCID 或指定作者实体建立人工确认关系，该关系的可信等级高于自动消歧结果。
6.1.2 无强标识情况下的评分
S_author = 0.30×S_name + 0.25×S_affiliation + 0.25×S_coauthor + 0.15×S_topic + 0.05×S_time
S_name 表示姓名相似度；S_affiliation 表示机构历史重合程度；S_coauthor 表示共同作者集合相似度；S_topic 表示论文主题或关键词向量相似度；S_time 表示发表时间范围的一致性。
评分区间 | 处理结果
S_author ≥ 0.95 | 自动合并
0.85 ≤ S_author < 0.95 | 进入人工复核队列
S_author < 0.85 | 保持独立研究人员实体

中文常见姓名和高频英文姓名采用更严格的自动合并条件。姓名完全相同仅用于候选召回。当候选作者缺少 ORCID，并且机构、共同作者和研究主题信息不足时，系统保持独立实体并等待后续数据补充。
6.2 机构消歧
来源记录包含 ROR ID 时，系统通过 ROR ID 直接关联机构主表。
来源记录缺少 ROR ID 时，系统首先匹配机构规范名称和别名表，然后结合国家或地区、城市、网站域名进行确认。
院系、实验室和研究中心按照机构层级关系保存，顶层机构使用统一机构实体。
机构更名、合并和拆分事件进入机构历史关系表，并且保存有效时间范围。
7. 多来源冲突数据处理方案
系统将字段冲突分为标识冲突、文本冲突、时间冲突、人员关系冲突、机构关系冲突和统计口径冲突。系统对每一个冲突字段保存候选值、来源、来源更新时间、可信等级和最终选值。
冲突类型 | 处理规则
DOI 冲突 | 通过 Crossref 校验 DOI；两个合法 DOI 指向不同登记记录时保持独立成果，并进入关系复核
题名差异 | 保存各来源题名；DOI 已确认时优先采用 DOI 登记元数据的题名作为主显示值；其他题名进入别名字段
作者列表差异 | 保留来源作者列表；主记录按照来源可信等级和出版记录确定作者顺序；差异进入数据质量标记
出版年份差异 | 同时保存 online_date、print_date、issue_year 等可区分日期；显示年份按照系统规定字段生成
机构差异 | 作者—机构关系携带时间和来源；同一作者在不同年份出现不同机构属于正常历史关系
引用次数差异 | 按照 OpenAlex、OpenCitations 等来源分别保存；系统禁止将不同口径的引用次数直接覆盖
专利法律状态差异 | 中国专利优先使用国家知识产权局公开信息；国际专利保存各主管机构或 EPO 来源状态和更新时间
奖励信息差异 | 授奖机构官方公告具有最高优先级；新闻稿、学校新闻和二次转载仅作为线索来源

7.1 来源可信等级
等级 | 来源类型 | 示例
A | 成果登记机构、主管机关、正式授奖机构 | Crossref DOI 登记元数据、国家知识产权局、国家科学技术奖励工作办公室、CCF 奖励官方公告
B | 专业开放学术数据库和标准身份库 | OpenAlex、DBLP、ORCID、ROR、OpenCitations
C | 科研机构官方网站和正式公告 | 大学、科研院所的成果页面
D | 新闻媒体、转载页面、搜索结果摘要 | 仅用于线索发现，正式记录需要回到 A/B/C 级来源确认

7.2 人工复核队列
复核类型 | 触发条件 | 复核结果
论文重复复核 | 论文相似度位于 0.82 至 0.92 | 合并、保持独立、建立版本关系
作者消歧复核 | 作者相似度位于 0.85 至 0.95 | 合并、保持独立、等待更多证据
奖励重复复核 | 奖励相似度位于 0.84 至 0.93 | 合并或保持独立
关键字段冲突 | A 级来源之间出现关键字段冲突 | 指定主值并记录审核说明
门户认领纠错 | 经认证科研人员提交成果归属纠错 | 管理员审核以后修正实体关系，并保留审计记录

8. 检索排序规则
以下规则作为 SPEC-SEARCH-01《检索排序规范》的主体内容。检索模块按照成果类型设置字段权重，并支持相关度、时间、引用次数等明确排序方式。
8.1 论文检索
论文默认相关度排序使用以下综合得分：
Score_paper = 0.80×R_text + 0.10×R_citation + 0.05×R_recency + 0.05×R_quality
其中各部分统一归一化到 [0,1]。R_text 使用字段加权的 BM25 相关度：
R_text = 0.45×Title + 0.20×Abstract + 0.15×Keywords + 0.10×Author + 0.05×Venue + 0.05×Institution
组成项 | 计算规则
Title | 题名 BM25 得分归一化
Abstract | 摘要 BM25 得分归一化
Keywords | 关键词与研究主题字段 BM25 得分归一化
Author | 作者姓名与作者别名匹配得分
Venue | 期刊或会议名称匹配得分
Institution | 作者机构规范名称与别名匹配得分
R_citation | 采用 log(1+citation_count) 计算，并在同学科、同发表年份范围内进行百分位归一化
R_recency | 采用 exp(-age_year/8) 计算时间衰减
R_quality | 按照 DOI、摘要、作者身份、机构标识等核心字段完整度计算

用户选择“最新发表”排序时，系统按照正式发布日期或可用的最精确发布日期倒序排列，并使用相关度作为同日期记录的第二排序键。用户选择“引用次数”排序时，系统按照指定引用来源的引用次数倒序排列，并在界面中显示引用数据来源和更新时间。
8.2 专利检索
R_patent_text = 0.40×Title + 0.25×Abstract + 0.15×Applicant + 0.10×Inventor + 0.10×CPC
专利检索支持公开号、申请号的精确查询。精确标识符命中的记录排列在全文相关度结果之前。关键词检索采用题名、摘要、申请人、发明人和 CPC 分类加权排序。用户选择“最新公开”时按照公开日期倒序排列。
8.3 科技奖励检索
R_award_text = 0.45×ProjectName + 0.20×Person + 0.15×Organization + 0.10×AwardName + 0.10×Category
奖励检索提供授奖机构、获奖年度、奖励类别和奖励等级筛选。项目名称具有最高文本权重。当用户输入科研人员姓名时，主要完成人字段进入高权重匹配；当用户输入机构名称时，主要完成单位字段进入高权重匹配。
8.4 精确匹配加权规则
精确匹配 | 加权处理
完整 DOI | 对应论文固定排列在同一查询结果的首位
完整专利公开号或申请号 | 对应专利固定排列在同一查询结果的首位
完整 ORCID | 对应研究人员固定排列在研究人员结果首位
完整 ROR ID | 对应机构固定排列在机构结果首位
完整奖项编号（来源存在编号时） | 对应奖励记录固定排列在奖励结果首位

11. 一期实施范围与推荐顺序
第一步完成 OpenAlex 论文采集，建立论文、作者、机构、期刊或会议和学术领域的基础数据结构，并且完成一万条以上论文数据入库。
第二步接入 Crossref，通过 DOI 校验和补充出版元数据，并且完成跨来源论文去重。
第三步接入 DBLP，对计算机领域论文、会议和作者记录进行补充，并且验证作者消歧方案。
第四步接入 ORCID 和 ROR，将研究人员身份标识和机构规范标识加入学者门户与实体消歧流程。
第五步接入国家知识产权局公开专利数据，并且建立专利公开记录、申请实体和专利家族关系。
第六步接入国家科学技术奖励工作办公室、CCF 和中国电子学会公开奖励数据，并且建立来源适配器和奖励复合去重规则。
第七步建立统一检索索引，完成论文、专利、奖励三个成果类型的搜索、筛选、排序和详情展示。
第八步建立数据质量仪表板，展示采集任务状态、字段完整率、重复候选数量、人工复核任务数量和异常记录数量。

12. 数据合规与工程风险控制
数据采集程序优先调用公开 API 和官方数据下载服务。页面采集程序遵循目标网站的使用条款、访问频率和机器人访问规则。
收费数据库、需要机构授权的数据库和受版权保护的全文内容仅在获得明确授权以后接入。
论文摘要、专利全文和附件等可能涉及版权许可差异的内容需要在来源表中保存许可字段，前端展示功能按照许可状态控制。
用户门户认领期间提交的身份材料按照最小化原则处理，审核完成以后仅保存业务需要的验证结果和审计记录。
每一次自动合并和人工修正均记录操作者、时间、规则版本、合并前实体和合并后实体，从而支持追踪和回退。
13. 调研结论
学术成果分享平台的一期数据建设可以形成“OpenAlex 主论文库 + Crossref DOI 校验 + DBLP 计算机领域补充 + ORCID/ROR 身份规范 + OpenCitations 引用补充 + 国家知识产权局中国专利 + EPO 国际专利补充 + 官方奖励机构目录”的数据来源体系。
统一数据治理流程需要以标准标识优先、来源追踪、字段级冲突管理、分级自动合并和人工复核为核心。论文去重优先使用 DOI，专利记录优先使用公开号和申请号，科技奖励使用授奖机构、年度、类别、等级、项目名称、完成单位和完成人构成的复合信息。作者消歧优先使用经过验证的 ORCID，机构消歧优先使用 ROR。
检索模块需要对论文、专利和科技奖励分别建立字段权重。论文默认相关度同时考虑文本相关性、同领域同年份引用影响、时间因素和数据完整度；专利检索重点考虑题名、摘要、申请人、发明人和 CPC；奖励检索重点考虑项目名称、主要完成人、完成单位和奖项分类。
