# 学术成果分享平台需求分析

## 第1页 需求分析范围与核心业务

平台整合论文、专利、科研项目和获奖信息，支持公众检索成果、科研人员认领门户、管理员采集和治理数据。1组与2组依据相同需求基准分别开展分析。

| 核心业务 | 输入 | 需要得到的结果 |
| --- | --- | --- |
| 数据采集入库 | 数据源、固定范围、解析与处理规则 | 可追溯的规范成果、来源关系和处理记录 |
| 门户认领审核 | 申请人、目标门户、证明材料 | 明确的审核结果和经过授权的门户管理权 |
| 检索请求处理 | 关键词、人物、机构、类型及筛选条件 | 同一公开版本中的可见结果、总数与详情 |

分析围绕业务对象、对象关系和关键交互展开。以下分别介绍1组与2组如何处理这些业务。

## 第2页 1组 业务对象的属性 行为与关联

平台可能先采集学者信息，本人再注册和申请门户，因此Account、Scholar和ScholarPortal分别维护，通过PortalAuthorization记录管理权。

| 业务对象 | 核心数据 | 业务行为 |
| --- | --- | --- |
| Work规范成果 | 成果ID、题名、数据版本、来源证据 | 校验后更新，解析合并后的规范ID |
| Contribution成果贡献 | 角色集合、确认状态、证据、有效区间 | 确认贡献或撤销本人关系 |
| ClaimApplication认领申请 | 状态、材料版本、申请版本、私有证明 | 提交、补充、批准、驳回和撤回 |
| SourceRecord原文版本 | 来源键、checksum、原文引用 | 保留原文版本，比较内容是否变化 |

**关联约束：**每条Contribution属于一个Work，贡献主体为学者或机构之一。当前有效门户授权在账号和门户两侧均至多一条，历史授权保留。

**成果继承：**Paper、Patent、Project、Award继承Work。PatentDocument表示专利文献，不能作为额外一件申请级成果重复统计。

## 第3页 1组 采集入库的处理与恢复

采集控制对象固定来源、范围和规则，执行器取得有效attempt后获取数据。原文先保存，清洗和身份匹配后再写入规范成果。

| 处理阶段 | 对象协作与约束 |
| --- | --- |
| 接收来源 | SourceRecord保存不可变原文版本，CollectionObservation记录本次观测 |
| 清洗匹配 | 校验字段、生成比较键；可信强标识一致且无冲突时创建或关联成果 |
| 质量处置 | 弱证据和冲突进入GovernanceReview，非法记录隔离，技术错误记录ERROR |
| 规范入库 | 成果、贡献、来源映射、UpdateRecord及后续工作共同提交 |

**页提交**共同保存来源引用、观测及处理登记和下一cursor。**整窗成功**要求输入均有可靠处理结果，才提交SUCCEEDED并推进successWatermark。

**恢复案例：**第一页已提交，第二页解析失败。保留第一页，从第二页恢复，整窗成功水位不前进。重复原文可以复用，但未完成的处理不能跳过，旧attempt也不能回调成功。

配图：[1组采集入库主图](图件/1组/03-采集入库时序图.png)、[清洗去重子交互](图件/1组/03a-清洗去重子交互.png)。

## 第4页 1组 门户认领的审核与并发控制

申请人已登录且科研身份审核通过，提交目标门户和私有证明。ClaimControl协调申请、授权和审核记录，审核人只能读取其权限范围内的材料。

| 交互步骤 | 状态与处理结果 |
| --- | --- |
| 有效提交 | DRAFT进入PENDING_REVIEW，保存申请和材料版本 |
| 要求补充 | 进入NEED_MORE_INFO，说明缺项；有效补交后回PENDING_REVIEW |
| 批准 | APPROVED、PortalAuthorization、ReviewRecord和审计共同提交 |
| 驳回或撤回 | 保存理由与历史，不创建管理授权 |

批准提交时复验资格、审核权限、当前申请及材料版本，检查账号和门户两侧有效授权唯一性。任何一项写入失败，事务整体回滚。

**并发案例：**双方均读取version=7，撤回先提交后状态为WITHDRAWN、version=8。管理员的旧批准必须失败，不能覆盖撤回或创建授权。批准先提交时，普通撤回失败，解除管理权另走授权撤销。

配图：[1组认领审核主图](图件/1组/05-门户认领审核时序图.png)、[原子授权与撤回子交互](图件/1组/05a-认领原子授权与撤回子交互.png)。

## 第5页 1组 检索语义与结果一致性

检索控制对象接收条件，确认人物身份，固定公开版本，再调用查询与公开读取职责返回结果。公开查询允许匿名访问。

| 处理环节 | 具体设计 |
| --- | --- |
| 人物机构筛选 | 同名先选人物ID，沿同一Contribution及ContributionAffiliation匹配机构 |
| 同版读取 | PublicRelease与ReleaseEntry固定列表、续页、详情的内容及来源 |
| 计数与分页 | 当前权限先约束候选集合，total、分面和分页从同一集合计算 |
| 返回前校验 | 复验权限修订；变化时作废结果并要求重试，不返回旧计数或部分列表 |

**查询案例：**A01在I01的成果为R01、R04、R07，共3条。R06中A01属于I03、另一作者属于I01，不能交叉匹配后加入结果。

**分页与异常：**实际total=3、每页2条，第3页越界。合法空集与超时分别处理；指定公开版本失效时提示刷新，不能改读最新数据掩盖错误。

配图：[1组贡献机构关系](图件/1组/02-局部03-贡献机构与领域关系.png)、[检索权限与分页子图](图件/1组/06a-检索权限计数与分页子交互.png)。

## 第6页 2组 业务对象的职责与关系

2组以User、Scholar、AcademicOutcome、各类申请、CrawlTask、SourceRecord和UpdateRecord组织身份、成果与数据处理职责。

| 对象及关系 | 核心数据 | 业务行为 |
| --- | --- | --- |
| User、Scholar | 账号角色和认证状态，学者标识、来源与门户资料 | 校验申请资格，区分同名人物，维护门户 |
| AcademicOutcome、OutcomeContributor | 规范成果身份，贡献角色、顺序、确认状态及署名机构 | 校验成果，确认或撤销贡献关系 |
| PortalClaim、ResearcherOutcomeClaim | 申请目标、材料证据、版本、状态及审核意见 | 分别处理门户管理申请与成果贡献申请 |
| CrawlTask、SourceRecord、UpdateRecord | 固定采集范围、原文版本、处理结果与变更依据 | 调度恢复、来源追踪及更新登记 |

**关联约束：**每份PortalClaim对应一个申请人和一个目标学者门户，有效管理绑定两端均为0..1。每条贡献明细属于一个成果，一项成果可有多条贡献。

**成果继承：**Paper、Patent、ResearchProject、Award继承AcademicOutcome。单位奖未列个人时保留单位贡献，不补造人员。

配图：[2组核心业务类图](图件/2组/01_核心业务类图.png)。

## 第7页 2组 采集入库的主交互与异常处理

管理员或调度器创建固定范围任务，采集控制对象登记任务与执行尝试，从有效断点读取来源数据。

| 主交互 | 正常处理与输出 |
| --- | --- |
| 读取并验证响应 | 保存原文版本、哈希和观测，相同内容只新增观测 |
| 清洗与归并 | 映射类型字段，依据强标识查找规范对象，返回候选及证据 |
| 入库事务 | 规范成果、贡献、来源映射、更新、后续登记和分页断点共同提交 |
| 整窗结束与发布 | 全范围处理校验后提交SUCCESS和成功水位，另行构建并发布索引统计版本 |

**异常分流：**访问受限、解析失败与合法空页分别记录。弱证据进入复核，隔离或排除项保留原因与计数。失败不推进整窗成功水位，重跑不重复建成果。

**停止与恢复：**运行中先记录停止请求，执行器安全退出后才停止。失效执行尝试拒绝写入；索引发布失败继续提供上一公开版本，不能把补采直接标成已可检索。

配图：[2组数据采集入库时序图](图件/2组/02_数据采集入库时序图.png)。

## 第8页 2组 门户申请的验证与审核流程

科研人员提交本人门户的材料，验证通过后交由授权审核员处理。PortalClaim保存材料版本、审核占用、意见和历史关联。

| 交互阶段 | 状态与处理 |
| --- | --- |
| 材料提交 | 从DRAFT进入PENDING_VERIFICATION，校验身份、目标及重复申请 |
| 材料验证 | VERIFYING检查当前材料，通过后进入PENDING_REVIEW |
| 审核领取 | 有效占用成功后进入UNDER_REVIEW，读取有权访问的材料 |
| 补充或终审 | 缺项进入NEED_MORE_INFO，补交后重新验证；终审为APPROVED、REJECTED或WITHDRAWN |

批准时重新核对材料、对象、占用和有效绑定，批准结果、管理绑定和更新记录共同提交，保持账号和门户双向唯一。

**异常案例：**外部核验超时保留原因或转人工，不自动驳回。审核占用超时释放；旧材料或旧对象版本不能用于终审。批准与撤回竞争时最多一个合法提交，终审后的解绑另行处理。

配图：[2组门户认领审核时序图](图件/2组/03_门户认领审核时序图.png)。

## 第9页 2组 检索条件解析与同版结果返回

公众提交关键词、类型、人物、机构、领域、日期及分页条件。检索边界接收请求，检索控制协调公开版本、索引与成果读取。

| 交互阶段 | 具体设计 |
| --- | --- |
| 输入校验 | 检查年份范围和字段适用性，同名展示候选后使用人物ID |
| 条件组合 | 跨维度AND，同维度通常OR，多作者all或any明确，人物机构沿同一贡献匹配 |
| 查询与读取 | 固定release并检查当前权限，精确标识定位或文本查询，读取同版题录、贡献和来源 |
| 结果返回 | 稳定排序和分页，返回总数、分面、有效条件与版本，保存查询上下文 |

**版本案例：**列表已绑定R1，此后R2发布，续页和详情仍读取R1。R1失效则明确提示刷新，不能静默换版。

**错误区分：**非法条件提示修改，合法空集显示0条，超时或读取失败返回服务错误。查询不在请求中临时访问外部来源补齐字段，私人证明不进入公开结果。

配图：[2组检索请求处理时序图](图件/2组/04_检索请求处理时序图.png)。

## 第10页 需求分析结论与简要对照

| 业务规则 | 模型需要保证的结果 |
| --- | --- |
| 成果与来源可追溯 | 规范成果能够定位原文版本、贡献关系和修改依据 |
| 失败可恢复 | 已提交数据保留，断点有效，整窗水位不提前推进 |
| 门户管理权受控 | 身份与权限分开判断，批准和绑定原子提交，并发不重复授权 |
| 查询结果可信 | 同人同机构匹配正确，列表、总数、详情的版本与权限一致 |

**两组的主要差异：**1组独立展开授权、观测和公开版本对象；2组集中表达部分职责，并单列成果认领申请。当前认领六状态与九状态、重试耗尽后的终态仍需按共同需求统一。

后续实现据此落实唯一约束、版本检查、可靠更新登记与公开版本读取，并通过重复采集、并发审核、同贡献筛选和版本失效等场景验证。
