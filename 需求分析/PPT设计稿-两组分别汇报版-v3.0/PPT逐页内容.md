# 学术成果分享平台需求分析汇报

## 第1页 共同需求与分析任务

两组基于相同的需求基准，分别完成学术成果分享平台的需求分析。

| 分析任务 | 需要回答的问题 |
| --- | --- |
| 识别业务对象 | 平台管理哪些人、成果、申请和数据记录？ |
| 建立核心业务类图 | 对象具有什么属性和行为，彼此如何关联？ |
| 建立关键交互模型 | 采集、认领、检索如何完成，失败或并发怎样处理？ |

汇报顺序：先介绍1组的业务类与三条关键流程，再介绍2组的对应设计，最后归纳两组的具体差异。

## 第2页 1组 核心业务类设计

1组建立28个业务类、45条关系，将需要保留独立历史的授权、贡献机构、采集观测和公开版本单独建模。

| 关键对象 | 保存内容与职责 |
| --- | --- |
| PortalAuthorization | 保存账号对门户的有效授权及撤销原因，通过revoke解除管理权 |
| ContributionAffiliation | 保存某次成果贡献发生时的机构关系，支持同人同机构检索 |
| CollectionObservation | 保存每次采集观测的批次、规则版本和处理结果 |
| PublicRelease、ReleaseEntry | 固定公开版本及其成果、关系和来源快照 |

Work统一论文、专利、项目和获奖的公共信息。专利另分为申请Patent、文献PatentDocument和家族PatentFamily，避免将两份文献计成两件成果。

**关系约束：**账号身份、门户管理权和成果贡献分别判断；当前有效授权在账号和门户两侧均至多一条。

## 第3页 1组 数据采集入库

1组将原文保存、规范入库和完整窗口结束划分为不同提交边界。

| 提交边界 | 共同保存的内容 | 成功后推进什么 |
| --- | --- | --- |
| 页提交 | 来源引用、观测及处理登记、下一断点 | 分页cursor |
| 规范入库 | Work、贡献、来源映射、UpdateRecord和后续工作 | 规范处理结果 |
| 整窗完成 | 窗口完整性核对、任务成功状态 | successWatermark |

**恢复案例：**第一页已经提交，第二页解析失败。第一页数据保留，从第二页恢复；整窗成功水位保持原值，直到全部处理可靠完成。

相同来源键与checksum复用原文版本，尚未完成的处理继续执行。旧attempt失效后，迟到的写入和成功回调均不能推进任务。

当前图中以SUCCEEDED表示采集成功，重试预算耗尽进入STOPPED。索引发布另外确认，失败时保留上一公开版本。

配图：[1组采集入库时序图](图件/1组/03-采集入库时序图.png)。

## 第4页 1组 门户认领与原子授权

1组认领采用六个业务状态：DRAFT、PENDING_REVIEW、NEED_MORE_INFO、APPROVED、REJECTED、WITHDRAWN。验证和审核占用作为处理过程或内部记录。

| 审核步骤 | 具体处理 |
| --- | --- |
| 申请提交 | 校验科研身份、目标门户、私有材料、重复申请和版本 |
| 审核决定 | 补充材料、驳回，或进入批准事务 |
| 批准提交 | APPROVED、PortalAuthorization、ReviewRecord及审计共同提交 |
| 冲突处理 | 复验申请与材料版本，检查账号和门户双向有效唯一性 |

**并发案例：**管理员与申请人均读取version=7。若撤回先提交为WITHDRAWN、version=8，旧批准必须失败且不能创建授权；批准先提交时，普通撤回失败，解绑另走授权撤销。

通知在提交后发送，通知失败可补发。写授权或审计失败时，批准事务整体回滚。

配图：[1组认领审核主图](图件/1组/05-门户认领审核时序图.png)、[原子授权与撤回子图](图件/1组/05a-认领原子授权与撤回子交互.png)。

## 第5页 1组 检索条件与返回一致性

1组通过Contribution与ContributionAffiliation约束人物和机构联合查询，并用公开版本与当前权限约束结果返回。

| 检索环节 | 具体规则 |
| --- | --- |
| 条件解释 | 同名先确认人物ID，人物和机构必须匹配同一贡献关系 |
| 内容版本 | 列表、续页和详情固定同一release |
| 计数分页 | 先得到当前允许集合，再计算total、分面和分页 |
| 返回检查 | 权限修订变化时作废本次结果，保留条件并要求重试 |

**关系案例：**查询A01在I01的成果，R01、R04、R07命中，共3条。R06中A01属于I03、另一作者属于I01，因此不命中。

**页码案例：**实际total=3、每页2条，第3页越界。页码上界在真实total返回后判断；合法空集跳过条目读取，仍复验权限。

配图：[1组贡献机构关系](图件/1组/02-局部03-贡献机构与领域关系.png)、[检索权限与分页子图](图件/1组/06a-检索权限计数与分页子交互.png)。

## 第6页 2组 核心业务类设计

2组建立15个业务类，以较集中的对象表达主要职责，部分细节保存在属性、关联和流程契约中。

| 关键对象 | 保存内容与职责 |
| --- | --- |
| Scholar | 保存人物标识、来源、识别状态及门户资料，账号通过管理关系关联 |
| AcademicOutcome、OutcomeContributor | 表达四类成果及人员贡献，保存角色、顺序、确认状态和署名机构证据 |
| PortalClaim | 保存门户申请、材料版本、状态、审核占用及历史关联 |
| ResearcherOutcomeClaim | 独立表达成果贡献确认或撤销申请 |
| CrawlTask、SourceRecord、UpdateRecord | 组织采集、来源依据与业务变更追踪 |

四类成果继承AcademicOutcome。成果与贡献使用组合表达归属，来源记录通过任务间的多对多观测复用。

**建模特点：**门户资料集中在Scholar，成果认领申请单独建模；公开版本和部分历史约束主要由交互及职责契约说明。

## 第7页 2组 数据采集入库

2组采集主交互用17条消息组织任务登记、来源读取、清洗归并、入库和公开更新。

| 消息阶段 | 具体处理 |
| --- | --- |
| 1至5 | 固定范围并登记执行尝试，读取响应，保存原文版本、哈希和观测 |
| 6至8 | 清洗字段，按强标识查找规范对象，返回候选与证据 |
| 9至11 | 同一事务提交规范成果、贡献、来源映射、更新及后续登记、分页断点 |
| 14至17 | 全窗口核对成功后推进水位，再构建和发布索引统计版本 |

**恢复规则：**已提交批次保留，失败不推进整窗成功水位，重复页面不能增加规范成果数。运行停止先记录请求，执行器确认安全退出后才停止。

当前图中以SUCCESS表示成功。预算耗尽或不可恢复时保持FAILED，不再自动调度；管理员明确放弃后才进入STOPPED。

配图：[2组数据采集入库时序图](图件/2组/02_数据采集入库时序图.png)。

## 第8页 2组 门户认领审核

2组采用九状态，将验证与人工审核的处理阶段也纳入申请状态。

| 阶段 | 状态及处理 |
| --- | --- |
| 提交与验证 | DRAFT有效提交后进入PENDING_VERIFICATION，验证阶段为VERIFYING |
| 人工审核 | 验证通过进入PENDING_REVIEW，审核占用成功进入UNDER_REVIEW |
| 材料补充 | NEED_MORE_INFO保存缺项，补交后材料版本递增并重新验证 |
| 终审结果 | APPROVED、REJECTED、WITHDRAWN保留历史 |

批准时同一事务建立有效门户管理绑定并保存更新记录，账号及门户两侧有效绑定唯一。

**异常案例：**外部核验超时，保留待验证原因或转人工，不自动驳回。审核占用超时释放，旧版本决定被拒绝。批准与撤回竞争时，同样只能有一个合法提交。

配图：[2组门户认领审核时序图](图件/2组/03_门户认领审核时序图.png)。

## 第9页 2组 检索请求处理

2组检索主交互用14条消息表达输入校验、固定公开版本、索引查询、同版读取与结果返回。

| 消息阶段 | 具体处理 |
| --- | --- |
| 1至3 | 校验条件、类型、日期和分页，同名先显示候选再使用人物ID |
| 5至6 | 固定release，检查版本可用性及当前可见权限 |
| 7至8 | 精确标识定位或文本查询，执行过滤、稳定排序、分页和分面 |
| 9至11、14 | 根据规范ID读取同版题录、贡献和来源，保留查询上下文 |

**版本案例：**列表绑定R1后R2发布，后续分页和详情仍读取R1；R1失效则明确提示刷新，不能静默换成R2。

非法条件、合法空集、服务失败和版本失效分别返回。人物与机构仍须满足同贡献语义，私人证明不能进入公开结果。

配图：[2组检索请求处理时序图](图件/2组/04_检索请求处理时序图.png)。

## 第10页 两组设计差异与需要统一的问题

两组从相同需求基准出发，区别体现在对象拆分和当前交付模型的具体表达。

| 对照项 | 1组 | 2组 |
| --- | --- | --- |
| 门户和授权 | ScholarPortal、PortalAuthorization独立建模 | 门户资料集中在Scholar，管理权通过关联表达 |
| 来源与公开数据 | 独立观测、映射、公开版本和条目 | 部分信息集中在来源记录及流程契约中 |
| 成果认领申请 | 当前类图未独立展开 | 单列ResearcherOutcomeClaim |
| 页断点提交 | 与来源引用、观测及处理登记共同提交 | 与规范成果及后续登记共同提交 |
| 门户状态 | 六状态 | 九状态 |
| 重试耗尽 | STOPPED | 保持FAILED，人工放弃后才STOPPED |

**可保留的共同规则：**原文可追溯、同贡献筛选、失败不推整窗水位、批准与授权原子提交、同版读取与当前权限校验。

**需要统一：**认领状态集合、任务成功命名及重试终态。两组应依据共同需求逐项复核，并同步修订状态图、时序图和验收场景。
