# 第一版实现决策（2026-11-06）

基线：前期成果中的 SRS v1.1、SPEC v1.1 和需求分析报告 v1.0。Windows 桌面是明确交付目标。

## 技术与边界

- `frontend/`：C# / WPF 原生控件，.NET 9（匹配本机 SDK），HttpClient 异步访问 API。无需浏览器或 WebView；服务地址可配置。后续部署前升级到受支持的 .NET LTS。
- `backend/`：Java 21、Gradle 9.8、Spring Boot 4.1.2、Spring JDBC。官方 [Boot 系统要求](https://docs.spring.io/spring-boot/system-requirements.html) 支持 Gradle 9；不采用仅声明支持 Gradle 7/8 的 Boot 3.5。
- 本地 H2 文件库；服务器 PostgreSQL。Flyway 管理同源迁移；H2 测试不能替代 PostgreSQL 验收。
- 4 核 4 GB 首版采用模块化单体，不引入 Elasticsearch、Redis 或消息队列。查询有分页上限、索引、有限缓存；复杂查询和共著搜索有边界。
- 访问令牌随机生成，仅保存摘要；密码用 PBKDF2。演示账号仅本地 demo 模式启用，生产启动必须提供管理员密码。

## 数据与一致性

统一成果保存类型、时间含义与精度、来源和模拟标识；强标识归并，弱题名不自动归并；来源快照不可覆盖。账号身份、门户绑定、成果贡献分别授权。

采用数据库事务 + 行锁 + 版本条件更新保障审核与撤回竞争；数据库唯一约束防止重复门户绑定、重复贡献和重复在审申请。所有审核持久化审计。仅进程内 synchronized 不能作为多副本写入保障。

第一版公开目录以追加式发布版本组织，检索/详情/统计接受相同版本号；旧版本继续可读。导入事务原子发布，保留原始输入和来源哈希；不伪称已经实现异步索引发布或联网采集适配器。后续修订/删除需要新增不可变成果版本与过期机制。

## 分阶段交付

1. 工程骨架、架构与范围基线。
2. API、数据库、登录和审核闭环、结构化导入、检索/统计/共著证据、关键并发测试。
3. 可构建运行的 Windows 桌面界面及端到端演示。
4. Docker/k3s 模板、自动扩缩容、可复现压测、验收记录与运行说明。

## 首版范围

优先交付四类成果目录、筛选分页/详情、学者门户、身份审核、门户认领九状态、成果认领/撤销、来源追踪、结构化批次导入、分类统计及共著最短路径。所有模拟资料显式标记。

不把第一版等同于全部 P0 验收：真实数据源联网采集、可恢复分页采集与执行租约、软删除/纠错及归并治理、全文搜索引擎、P1 私人专题库/推荐等在验收映射中逐项标注后续项。没有通过测试的能力不标完成。

## 性能验证

按用户后续要求：本机不执行压测，只交付服务器运行脚本。服务器验收时用至少 10,000 条明确标识的模拟成果；20 并发，预热后持续 300 秒；记录查询集、请求数、错误率、p50/p95/p99、机器/JVM/数据库版本与冷热条件。搜索 ≤2 秒、详情 ≤1 秒、统计 ≤3 秒是基线目标。本地仅功能测试及两请求竞争的并发正确性测试，不产生或宣称 P95 达标结果。

## 资源预算

生产初始 1 个 API 副本（请求 250m CPU / 512 MiB，限制 1 CPU / 768 MiB），Hikari 8 连接；PostgreSQL 约 768 MiB；k3s 和系统预留至少 1 GB。HPA 最多 2 副本且采用延迟缩容。单机扩副本只能用剩余容量，不能增加物理容量；数据库仍是单点，应备份并监测连接数/磁盘。
