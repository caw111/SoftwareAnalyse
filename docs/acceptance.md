# v0.3 需求追踪

本表区分代码实现、功能验证和完整规模验收。基线为 [需求分析验收场景](../前期成果/需求分析/docs/需求分析验收场景.csv)，构件与数据模型见 [设计文档](design/component-design.md) 和 [ER](design/database-er.md)。

本轮已有 H2 功能测试通过记录；PostgreSQL、打包桌面和真实 Crossref 接通的结果以本轮最终验证记录为准。夹具验证不冒充真实来源，单次真实请求也不冒充批量稳定性或性能结论。

| --- | --- | --- |

## 本轮补充交付

- 管理员在桌面设置 DOI 或 ISSN/关键词、索引更新时间窗、出版年范围和数量预算，创建后显式启动任务；可查看原始页、错误、计数、水位及停止/重试进度。
- BOUNDED 限量任务完成不推进同步水位；INCREMENTAL 必须全窗完成，预算不足不标整窗成功；定时计划默认关闭。
- Crossref 固定域名 HTTPS、robots 核验、响应限额、源级持久化限流、Retry-After、条件请求缓存；其他来源尚未实现自动适配。
- V4 保留来源原文、规范修订、更新冲突和相同原文的规则重处理提案；当前冲突页只读，不伪装为已实现人工裁决。
- V5 同库倒排和加权 BM25，Unicode/中英词项、精确 DOI、AND 条件和稳定并列顺序；权重是固定基准，尚未完成大规模人工相关度评测。
- 热点按标题/摘要文档频次与业务年度计数，返回分母/覆盖数据/规则版本；数量频次不解释为学科确认或预测。
- 构件设计、来源核验矩阵、调度状态/提交时序图、31 表 ER Mermaid 与可编辑三页 draw.io。

既有交付继续保留：WPF 原生 Windows GUI、Java 21 API、独立登录/注册与三种角色工作区、资料编辑/认证面板、认领与撤销、共著 BFS 及论文证据、Docker/Compose/k3s/HPA 模板、服务器 k6 脚本。

## 性能验收边界

按用户要求，本机不运行压测。至少10,000条、20并发、预热5分钟的检索P95≤2秒、详情≤1秒、统计≤3秒仍为服务器验收目标；不将数据初始化、普通API耗时或功能测试写成P95达标证据。
