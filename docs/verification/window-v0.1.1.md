# v0.1.1 窗口与图标修复

用户反馈旧版窗口不能拖动且缺少右上角按钮，随后要求启动默认全屏。实现为**原生窗口默认最大化**：保留系统标题栏、任务栏和窗口操作按钮，点击还原后可拖动和缩放。

## 原因与修改

实际读取旧版 HWND：标准标题栏/系统菜单/最小化/最大化样式都存在，但固定 `1440 × 920` 与 `MinHeight=760` 在当前 200% 缩放下超出可用工作区。旧窗口左上角位于屏幕外，标题栏无法正常触及。之前的内容区截图未包含原生标题栏，因此没有发现这项问题。

现在在 HWND 创建后读取当前显示器工作区和 DPI，设置位于工作区内的还原尺寸和位置，再交给 Windows 执行最大化；不自绘或替换系统窗口按钮。明确选择初始“成果发现”页，避免自定义 TabControl 模板首次展示空白内容。

原创应用图标以书页和汇聚节点组成，SVG 为源，生成多尺寸 ICO 后分别配置 `ApplicationIcon` 和 WPF `Window.Icon`，同时用于侧栏和对话框。

## 实际验证

`scripts/verify-desktop-window.ps1` 启动真实 EXE，通过 Win32 读取原生样式、按钮坐标及窗口边界，并执行**真实鼠标点击与拖动**。测试结束关闭测试窗口。脚本会暂时使用鼠标，适合用户不操作电脑时运行。

- 当前 DPI：192，即 200%；物理工作区 2560 × 1504。
- 启动状态：最大化；三个标题栏按钮均在可用工作区内且可点击。
- 点击还原后外框：(102,75)–(2457,1428)，完整位于工作区内。
- 标题栏鼠标拖动后：(142,99)–(2497,1452)，位置按拖动正常改变。
- 点击最大化、最小化和关闭按钮均成功；原生图标句柄有效。
- WPF Release 构建 0 warning / 0 error；自带运行时 EXE 打包成功。
- 桌面冒烟通过：初始成果页可见，20 项成果、学者列表、统计和共著路径正常加载。
